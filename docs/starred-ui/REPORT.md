## Findings and corrections

The old star button used a rectangular UIPanel button with Unicode outline/filled
star text. That depends on client font coverage and can display missing-glyph
boxes. Shared guide, overlay, focused search and autocomplete controls now use
bundled `StarOutline.tga` and `StarFilled.tga`. These are deterministic five-point,
uncompressed 32-bit BGRA, 32x32 textures with alpha; the same local-file SetTexture
API already used by the accepted map pin loads them. No retail atlas, external
icon, font or new library is required. The star itself is the button artwork;
the UIPanel rectangle is removed. Preview remains read-only. Asset structure,
transparency, five tips, distinct center fill and exact generated bytes are
checked automatically. Native Forever texture loading/rendering still needs
in-game confirmation.

The compact header previously subtracted each action button from the name width,
leaving very narrow wrapped text and controls in the identity band. Shared rows
now place actions in a top-right strip with disjoint click targets, then item
icon/full wrapped name, level/status, comparison and acquisition/material details.
The full guide measures name and metadata heights before positioning the level,
profession, comparison and source blocks. The guide's applicable progress/map/star
actions also occupy the top strip. Profession metadata and material headers
reserve measured space at narrow widths. Minimum/wide resize paths recalculate
text widths and heights; background, expansion targets, spacing and scrolling
use those measured heights. Search results retain full names in measured rows
with their own action strip and a scrollable result list; arrow selection keeps
the selected result in view. The focused card keeps its existing scrolling body.
There is no item-, slot- or class-specific offset.

The state investigation confirmed that saved numeric-ID stars and deterministic
composition already sort correctly on ordinary toggles in the offline harness.
The precise reported native-client failure could not be reproduced there. The
presentation path did leave pagination/scroll position unchanged, did not
explicitly commit native scroll-child rectangles after same-size reordering,
and allowed an empty guide placeholder to retain its former reusable item body
identity. A production UI regression reproduces the latter: render an item,
render an empty list, then bring the same item back via a targeted future star;
the placeholder must be replaced by the item's actual rendered body.

The targeted refresh now assigns a dense reusable row pool to sorted positions,
invalidates placeholder and hidden pooled-body identities, updates headings/counts and commits changed
scroll rectangles. Starring selects the first page/top of the starred section,
without writing either saved equipment-slot selection. Unstarring recomposes
against the ordinary model, retaining ordinary ordering and eligibility. Existing
row bodies retain their measured content. Source-derived recommendation records
are constructed only for entering rows; already rendered stars no longer repeat
that source work before their reuse check. A cold collapsed objective section
allocates no off-screen objective rows on a star click.

## Measured comparison

The unchanged fourteen production overlay/inventory/loot/gathering workloads
were compared to independently Git-object-verified `.11` in three interleaved
runs per interpreter. Calculation counts and ordered recommendation/material
fingerprints were identical in every case. Warm refreshes create zero new frames.
The first full guide creates forty additional texture regions, one per guide
star; the rendered guide pool remains capped at forty rows. The full raw
comparison retains timing/heap variation: separate-process Lua 5.1 medians
included -38.69% for the warm-overlay batch, while Lua 5.4's corresponding median
was +64.73%. These noisy measurements prompted the paired check below; they are
not omitted from the delivery.
