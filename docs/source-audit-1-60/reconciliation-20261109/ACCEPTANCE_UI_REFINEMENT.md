## 1. Marker names

`MapNavigation.lua:refreshMarker` itself prefixed every rendered label with `GetGear:` and appended ` (published area)` for area targets. This formatting was independent of correct coordinates or successful rendering. The user described the prefix as `Gear:`; the inspected baseline renderer spells it `GetGear:`. Both are absent from the new primary name.

New `GetAcquisitionMarkerLabel` returns the source/objective's existing destination name. Ordinary dungeon markers use the canonical dungeon name; genuinely different gates retain their distinguishing entrance labels, with the known publication suffix removed from primary text. Example: `GetGear: Va'yn Moongaze (published area)` → `Va'yn Moongaze`; Shadowfang approach → `Shadowfang Keep`; Stratholme retains `Living Side Entrance` versus `Undead Side Entrance`. Names are not rewritten in source records: the current independent actor254151 is spelled `Vayn Moongaze` in the data, and that spelling remains unchanged where used.

Only the primary rendered text changes. `target.verification`, point/area coordinates, bounds, source identity, requirements and native/published distinctions remain intact. Existing compact pin tooltip says a published area is not an exact NPC position; full guide directions retain the explicit area ranges and all provenance. Marker footprint drawing, delayed canvas state, map switching, one-marker reuse/cleanup and native waypoint behaviour are unchanged and regression-tested.

## 2. Source-aware compact recipe summaries

`AcquisitionNavigation.lua:GetAcquisitionCompactSummary` reused the same verbose vendor/trainer location format: individual NPC, zone, alternative count and a generic research disclaimer. `AcquisitionSummary.lua:GetAcquisitionSummary` selected that text before any concise trainer summary. This was presentation reuse, not an incorrect recipe skill.

New shared `GetCompactRecipeSummary`, called first by `GetAcquisitionSummary` and by the compact contextual helper, uses existing acquisition-method/skill evidence. Embossed Leather Vest **2300**, exact taught spell2160/skill35, now displays **`Recipe: Leatherworking trainer (35)`**. The old Alliance/unknown-faction output was `Recipe source: Leatherworking 35; Adele Fielder — Elwynn Forest; 3 other qualified location(s) (published reference; current stock/access unverified).` In the baseline, explicitly mocked Horde faction already filters those four Alliance-only destinations and returns no sentence. The literal reported Horde sentence is therefore not independently reproduced with a known Horde API result; no inference about the user's actual installed build/API state is made. New concise text passes for Alliance, Horde and unknown faction; no Horde navigation destination is fabricated.

Routine formatting requires existing explicit trainer-method evidence, or multiple independently matched full teaching tables with consistent spell/minimum, no competing pattern or restricted route and no historical/disputed gate. A single mentioned teacher alone is insufficient. Unknown minima remain `skill unverified`; skill-up colour thresholds never become a minimum. A known trainer-method record is not a guarantee of current teaching by every NPC.

Other structured recipes retain the useful acquisition method: named accessible vendor, named recipe-book drop/dungeon source, or quest and its prerequisites. For example, Shining Gown253971 uses `Recipe: Mivin Shadowweave (Tailoring 110)` plus its actual currency/faction/stock qualifications. Random-drop references remain random, not targetable or guaranteed. Disputed teaching, historical-only references and uncertain stock/access remain qualified. Offer costs (including material currencies), reputation, quest minimum/side and typed source requirements are retained. Explicit `Published requirement:` clauses that only exist in older reviewed prose are carried verbatim into the compact summary, preserving Friendly Earthen Ring/Kirin Tor gates without rewriting records. Complete alternatives, IDs, provenance and detailed learning/crafting distinctions remain in the existing full-guide formatter and navigation data.

No UI layout function changed: compact text uses the existing measured wrapping/row height; no new controls, panels or icons. Recipe knowledge/visibility, materials tracking and all filtering/saved settings are untouched.
